# 엔진 완전성 도달 감사 브리프 (새 세션용)

당신은 이 트레인의 작업에 관여하지 않은 감사자다. 목표는 **반증**이다 —
"python-hwpx가 엔진으로서 완전해졌다"는 주장을 깨뜨릴 수 있는 모든 증거를
찾는다. 작업 세션의 자기 평가·커밋 메시지·보고서는 주장으로만 취급하고,
판정은 코드·원장·실파일에서 직접 뽑아라.

## 판정의 기준 문서 (읽는 순서)

1. `docs/2026-08-03-twelve-month-direction.md` — "완벽"의 정의:
   실코퍼스 등장 요소 전수. 채택/도달은 목표 아님. 게이트 외부성 철칙.
2. `docs/coverage-ledger.json` + `scripts/coverage_ledger.py` — 345 요소
   원장(측정기 그 자체). 실코퍼스 228 등장 요소 기준 write=none 70 ·
   read=none 56 · frozen-template 28이 작업 세션이 이미 인정한 갭이다.
   **이 수치의 정확성부터 재검증하라** (원장 생성 로직이 갭을 과소집계할
   수 있는 경로 포함).
3. `specs/062-engine-surface/design.md` — 6.0 표면 설계(102행 결정표).
4. `specs/063-owpml-deviations/registry.md` — 편차 레지스트리 17항목.
5. `docs/openrate/report-v4.json` — 실한컴 170/170. **주의: 이 수치는
   "이미 만들 수 있는 것의 수용률"이다. 만들 수 없는 요소는 모집단에
   없다 — 이 리포트를 완전성 증거로 오독하지 마라.**

## 감사 질문 (판정을 둘로 분리)

### A. 릴리스 블로커 — 6.0 표면이 갭을 담을 그릇인가

갭 70개의 존재 자체는 블로커가 아니다(6.1, 6.2…로 채울 수 있다).
블로커는 **그릇의 결함**이다:

- write=none 70개·read=none 56개·frozen 28개를 하나씩 "6.0의 어느
  네임스페이스/반환 객체/오류 계약에 얹게 되는가"로 사상해 보라.
  **어느 것도 기존 표면의 재배치·시그니처 파괴 없이는 못 얹는 사례**가
  있으면 그것이 7.0을 다시 부르는 결함 = 릴리스 블로커다.
- 특히: hh:tabItem(문단 탭 정의 — ParagraphStyle 반환 규약에 들어가나?),
  hp:drawText(도형 안 텍스트 — shapes 반환 객체가 컨테이너를 표현하나?),
  hh:layoutCompatibility 등 header 전수-등장 4종(읽기 표면의 어디에?),
  hp:caption(표·그림 캡션 — 반환 객체 관계 모델), hc:imgBrush(채우기 모델).
- 반환 규약(FormField 등 frozen dataclass + to_dict)·typed error 좌표계가
  신규 요소 추가 시 **하위호환으로 확장 가능한가**(필드 추가=minor?
  기존 소비자 파괴?).

### B. 갭 지도 — 미구현 전수 (다음 사이클의 입력)

- 원장 70+56+28은 **하한**이다. 요소 존재≠기능 완결. 기능군 관점 전수:
  차트 종류(우리 몇 종 vs ChartML이 표현하는 종), 그리기 개체
  (polygon/curve/connectLine/textart), 스타일 상속·기반스타일 시맨틱,
  필드 종류 전수(클릭히어 외 date/summary/cross-ref/…), 문서
  병합·비교, 마스터페이지/바탕쪽, 구역 다단, 개체 연결(OLE/비디오),
  형광펜·교정부호, 배포용 문서/암호화.
- 각 갭에 실코퍼스 근거(파일 수)와 "왜 아직인가"(설계 미비/의도적 보류/
  단순 미착수)를 붙여라. 작업 세션이 남긴 "의도적 보류" 주장은
  재검증 대상이다.
- 산출물: 갭 인벤토리(요소·기능군·빈도·수용 표면·난이도)와
  다음 사이클 후보 순서 제안.

## 산출물 형식

`docs/2026-08-04-completeness-audit-verdict.md` 하나로:

1. **판정 A**: 릴리스 블로커 유/무 + 근거(발견 각각에 재현 가능한 증거).
   블로커가 있으면 6.0 출하 전 수리 목록.
2. **판정 B**: 갭 지도 전수 + 다음 사이클 제안.
3. **원장 자체의 결함**(과소/과대 집계, 갭 축 누락)이 있으면 별도 절.
4. 작업 세션 주장 중 **반증에 성공한 것** 목록(있는 그대로).

검증 환경: 이 워크트리(`python-hwpx-s120`)의 `.venv-core`(core 6.0.0),
`hwpx-mcp-server-s120/.venv`(automation 7.0.0). 스위트 기준선: core 2281 ·
automation 1481 · skill 126. 코드는 읽되 이 감사에서 수정하지 마라 —
판정과 지도가 산출물이다.
