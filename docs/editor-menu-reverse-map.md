# 편집기 메뉴 표면 역매핑 (Menu → Engine Reverse Map)

`docs/editor-surface-inventory.md`는 "우리 능력 영역 → 실한컴 검증 상태"를
잰다 — 순방향이다. 이 문서는 반대 방향이다: **한컴 편집기 메뉴 항목 →
우리 대응**. 순방향 인벤토리가 "우리가 만든 것이 검증됐는가"에
답한다면, 이 문서는 "한컴이 가진 기능 중 우리가 아예 손 안 댄 게
있는가"에 답한다 — 사이클 6.12 트레인㊷, 2026-08-09. **트레인㊺(사이클
6.13, 2026-08-11)이 초판의 12건 [미확인] 전부를 실측 판정** —
스키마·코퍼스·코드 삼중 대조로 8건 확정, 4건은 실한컴 GUI 프로브가
필요해 "GUI 프로브 목록" 절에 남겼다(팀장 실행 대상). 상세는 각 표
행의 "트레인㊺ 판정" 인용과 아래 요약 절.

## 방법론

팀장이 macOS Hancom Office HWP에서 System Events로 메뉴바 13종 중
내용 관련 9종(파일·편집·입력·서식·쪽·표·도구·보안·보기)을 전수
열거했다(2026-08-08). 창·도움말·한글·Apple 메뉴는 스코프 밖(애플리케이션
자체 메뉴, 문서 형식과 무관)이라 스캔에서 제외됐다. **macOS 앱 기준** —
Windows 한컴 전용 표면은 이 스캔으로 부재를 단정할 수 없다.

각 항목은 4갈래로 판정한다:

- **[대응 영역]** — `docs/editor-surface-inventory.md`의 기존 캐파빌리티
  행(또는 지원 매트릭스 행)과 명확히 대응.
- **[부분 대응]** — 대응하는 메커니즘이 있으나 이 메뉴 항목이 요구하는
  전체 범위를 못 채움(뭐가 빠졌는지 명시).
- **[대응 없음=신규 갭]** — 코드 실사로 확인된, 대응하는 저작/편집
  경로가 전혀 없음.
- **[스코프 밖]** — 문서 형식(OWPML) 자체의 속성이 아니라 애플리케이션
  UI/대화형 편집 세션/언어 도구 등(근거 명시).

**추측 금지** — OWPML 표현 여부가 코드 실사만으로 불확실한 항목은
**[미확인]** + 확인 방법을 명시한다(무근거 승격도, 무근거 갭 선언도
하지 않는다).

이미 `docs/editor-surface-inventory.md`의 "편집기 실물 확인" 절
(2026-08-07, 부분 스캔)에서 판정된 항목은 그 판정을 그대로 인용하고
재조사하지 않는다 — 아래 표에 "(기존 판정 재인용)"으로 표시.

| 저장하기 | [스코프 밖] | `save_to_path`/`to_bytes` — 생명주기 |
| 다른 이름으로 저장하기… | [스코프 밖] | 상동 |
| 블록 저장… | [스코프 밖] | **트레인㊺ 판정(2026-08 사이클 6.13)**: 스키마 전수(`block`/`selection`/`clip` 등 관련어 grep — `imgClip`(그림 자르기)·`selectedValue`(양식 콤보값)만 매치, 무관)·코퍼스 전수(67파일)·코드 전수 어디에도 "블록만 저장" 마커 없음. | PDF로 저장하기… | [스코프 밖] | 렌더링/래스터화는 이 라이브러리의 스코프 밖이다 — 우리는 OWPML을 저작·편집·파싱하지 렌더하지 않는다(렌더 검증은 오라클=실한컴의 역할, `docs/openrate/*.json`이 이미 그 경계를 명시) |
| 편집 용지… | [대응 영역] | 페이지 레이아웃(`doc.page.set_size`/`.set_margins`) |
| 인쇄… | [스코프 밖] | (기존 판정 재인용) 편집 용지는 페이지 레이아웃이 대응·인쇄 다이얼로그 옵션 자체는 문서 상태가 아니라 스코프 밖 |
| 문서 정보… | ✅ [대응 영역] | ~~신규 갭~~ **트레인㊸ 갭①에서 해소**(`fac1a03`) — `doc.parts.set_document_metadata`가 `opf:metadata`(제목·작성자·주제·키워드·작성일·수정일)를 저작한다, v16 render-verified. `date`(자유형식) 필드는 다중 포맷 근거 부족으로 정직 보류 유지 |
| CCL 넣기… | [대응 영역] | **트레인㊺ 판정**: 스키마 전수에서 CCL 전용 요소는 없음 — 근접 후보 `hp:licensemark`(`Header XML schema.xml`, 속성 `type`/`flag`/`lang`)는 발견했으나 공유마당류 "저작권 표시 번호" 플래그라 CC 배지와 다른 개념. 코퍼스 67파일 전수(`공공누리`/`creativecommons`/`출처표시`/`이용허락`/`CCL`/`licensemark` 전부) 0건 — 실사용 근거는 없지만 실제 배지 예시가 없다는 것 자체가 "전용 요소가 있다"는 가설을 지지하지 않는다. CCL 삽입은 그림(`hp:pic`)+하이퍼링크(`hp:fieldBegin`)+텍스트의 **조합**일 뿐이라고 보는 게 더 근거 있다 — 셋 다 이미 대응(그림 삽입/치환·하이퍼링크·책갈피). 신규 요소 근거가 나오면 재조사 |
| 최근 사용 문서 | [스코프 밖] | 애플리케이션 UI 상태(최근 파일 목록) — 문서 자체 속성 아님 |
| 문서 닫기 | [스코프 밖] | 생명주기 |

## GUI 프로브 목록 (트레인㊺, 팀장 실행 대상)

아래 4건은 스키마·코퍼스·코드 전수로 안 갈려 실한컴 GUI 조작이 필요하다.
각 프로브는 "무엇을 어떤 순서로 조작하면 구조가 드러나는지"를 구체적으로
명시한다 — 결과(스크린샷·section0.xml diff·기록한 파라미터 값)를 넘기면
판정을 마무리한다.

### 프로브 1 — 날짜/시간 필드 (`hp:fieldBegin type="DATE"`/`"DOC_DATE"`)

1. 빈 문서를 새로 만들고, 입력 → 날짜/시간… 클릭. 옵션(자동 갱신
   켜기/끄기, 표시 형식 여러 종류)이 있으면 **각 조합별로 별도 파일**로
   저장한다(최소 2~3종: 자동갱신 on/off, 형식 다른 것 1~2개).
2. 각 파일을 zip으로 열어 `Contents/section0.xml`에서 새로 생긴
   `hp:fieldBegin`의 `type` 값이 정확히 `"DATE"`인지 `"DOC_DATE"`인지
   확인(옵션에 따라 갈릴 수 있음).
3. 그 안 `hp:parameters`의 모든 `stringParam`/`integerParam`의 `name`과
   값을 그대로 기록 — 특히 날짜 포맷을 표현하는 커맨드 문자열이 있는지
   (`PATH` 필드의 `Command="$F"`/`Format="$F"`와 같은 패턴인지, 다른
   포맷 코드 언어인지).
4. 문서를 닫았다 다시 열어(재계산 유도) 캐시된 `hp:t` 텍스트가 실제
   날짜로 갱신되는지 확인 — TOC의 `dirty="1"` 재계산 트리거와 유사한
   메커니즘이 있는지도 함께 관찰.

### 프로브 2 — 차례 숨기기

1. 개요 스타일이 적용된 문단 2개("제목 1", "제목 2")가 있는 문서를
   만들고, 도구 → 차례 만들기…로 TOC를 삽입(둘 다 수집되는지 확인) —
   이 파일을 baseline으로 보관.
2. baseline을 복사해 두 번째 파일을 만들고, "제목 2" 문단에 커서를 두고
   도구 → 차례 숨기기 클릭 후 저장.
3. 두 파일의 `section0.xml`을 diff — "제목 2" 문단 자신(`hp:p`)에 새
   속성/자식이 생겼는지, 아니면 TOC 필드(`hp:fieldBegin type="TOC"`의
   `hp:parameters` 안 `Command` 문자열)만 바뀌었는지 확인.
4. Command 문자열이 바뀌었다면 정확히 어느 부분이 바뀌는지(스타일
   화이트리스트에서 "제목 2"의 스타일이 빠지는지, 별도 exclude
   파라미터가 새로 붙는지) 원문 그대로 기록.
5. 문서를 다시 열어 TOC를 재계산시키고 "제목 2"가 실제로 목차에서
   빠지는지 최종 확인.

### 프로브 3 — 교정 부호 (`hp:fieldBegin type="PROOFREADING_MARKS"`)

1. 빈 문서에 문장 하나("이것은 시험 문장입니다.")를 입력하고 저장 —
   baseline.
2. 도구 → 교정 부호… 클릭 시 뜨는 대화상자의 옵션 전부를 스크린샷/기록
   (삽입·삭제·치환 등 표시 종류, 색상 지정 여부 등).
3. 아무 마크나 하나 실제로 삽입(예: 한 단어에 삭제 표시)하고 저장.
4. `section0.xml`을 baseline과 diff — `hp:fieldBegin type=
   "PROOFREADING_MARKS"`가 실제로 나타나는지, 나타난다면 그 `hp:
   parameters`의 전체 구조(각 파라미터의 `name`·타입·값)를 그대로 기록.
5. 변경추적(트랙체인지)이 꺼진 상태·켜진 상태 양쪽에서 반복 — 교정
   부호가 트랙체인지와 완전히 독립적인 별도 메커니즘인지, 아니면
   트랙체인지의 다른 표시 모드일 뿐인지 확인.

### 프로브 4 — 문서 보안 설정…

1. 빈 문서를 만들고 저장 — baseline (바이트까지 보관).
2. 보안 → 문서 보안 설정… 클릭 시 뜨는 대화상자의 옵션 전부를
   스크린샷/기록(복사 금지·인쇄 금지·배포 제한 등 정확히 어떤 항목이
   있는지 — "문서 암호 설정"과는 다른 다이얼로그이니 혼동 주의).
3. 옵션 하나만 켜고(예: 인쇄 금지) 저장 — 결과 파일을 baseline과
   바이트 단위로 대조. **완전히 동일하면** 이 설정이 애플리케이션
   레지스트리/OS 레벨에 저장된다는 뜻이므로 [스코프 밖]으로 확정
   가능(블록 저장·조판 부호 지우기와 같은 부류).
4. 바이트 차이가 있다면 어느 파트(`Contents/settings.xml`?
   `content.hpf`? `section0.xml`의 `secPr`?)에 무엇이 추가됐는지 diff
   결과를 그대로 기록.
5. 옵션을 여러 개(가능하면 전부) 조합해 반복 — 항목별로 별도 플래그인지
   하나의 비트마스크인지도 함께 확인.
